# Decision Log

| Context | Options | Chosen | Why | Cost | Revisit when |
|---|---|---|---|---|---|
| Initial deployment and module boundaries | Microservices; modular monolith | Modular monolith with domain/application/infrastructure packages | One deployable keeps local development and transactions tractable while explicit boundaries preserve extraction options | Requires architecture tests and discipline to prevent package coupling | Independent scaling or ownership needs outweigh operational overhead |
| Domain model and persistence | Annotated JPA entities as domain; pure domain mapped to persistence entities | Pure Java domain with explicit infrastructure mapping | Business rules remain testable without Spring/JPA and persistence changes do not dictate the model | More mapping code and separate persistence models | Mapping becomes a measured bottleneck or a module has a justified simpler model |
| Checkout across payment and stock | One long transaction; synchronous distributed coordination; reservation-based saga | Persist pending order/reservation, call gateway outside DB transaction, finish through idempotent confirmation | Avoids holding database locks over network calls and gives crashes a recoverable state | Requires TTL cleanup, reconciliation, and compensating actions | Payment provider offers a reliable atomic primitive spanning the required operation |
| Domain dependency enforcement | Convention only; code review; automated architecture test | ArchUnit test in the build | Makes forbidden framework and cross-module domain dependencies fail CI | Test imports package classes and rules need updates when boundaries intentionally change | Modules are extracted into separately compiled artifacts |
| Monetary representation and rounding | `double`; integer minor units; `BigDecimal` with `Currency` | `Money` value object using `BigDecimal`, normalized to the currency scale with `HALF_EVEN` | Decimal arithmetic avoids binary floating-point errors and supports currencies with different minor-unit scales | Rounding occurs whenever a `Money` value is created; provider-specific settlement rules may differ | A provider requires a different explicit rounding policy or measured throughput justifies minor-unit arithmetic |
| Entity identity in domain APIs | Raw UUID/String; typed identifier wrappers | UUID-backed records such as `OrderId` and `UserId` | Prevents accidental mixing of identifiers while retaining straightforward persistence mapping | Adds small value types and explicit mapping at adapter boundaries | A module needs a non-UUID identifier or public API format |
| Domain event delivery boundary | Direct calls to Spring; direct Kafka dependency; application port | Framework-free `DomainEvent` contract and `EventPublisher` application port | Keeps domain/application callers independent of the initial event adapter and permits outbox/Kafka implementations later | The infrastructure adapter and delivery guarantees still need implementation | Event volume or module deployment requires asynchronous broker delivery |

Additional trade-offs are recorded alongside the modules that introduce them.
